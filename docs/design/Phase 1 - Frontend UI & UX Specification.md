# Phase 1 — Frontend UI & UX Specification

## Objective

Design the first user experience of Wasal by creating a modern, clean, and trustworthy interface that introduces the platform before users interact with the AI assistant.

This phase focuses only on the frontend design and user experience. No backend integration is required at this stage.

# User Access Model

Wasal supports two different user experiences.

## Guest User

Guest users can:

- Access the Landing Page.
- Explore the platform.
- Open the Wasal AI Assistant.
- Ask general questions about government complaints.
- Learn about government authorities.
- Receive general guidance from the AI assistant.

Guest users cannot:

- Start the complaint generation process.
- Save complaints.
- Save conversations.
- Access the Dashboard.
- View previous complaints.

---

## Logged-in User

Logged-in users have access to all Guest features, plus:

- Start a new complaint.
- Generate a professional complaint.
- Save complaint drafts.
- Save conversations.
- Access the Dashboard.
- Continue unfinished complaints.
- View previous complaints.

# Background Style

Use the same Off-white background.

Very subtle geometric or organic pattern is acceptable.

Avoid heavy illustrations.

---

# UX Principles

The platform should feel:

- Easy to use
- Friendly
- Clear
- Minimal
- Government-grade
- Modern

Avoid unnecessary complexity.

---

# Responsive Design

The UI must be responsive for:

- Desktop
- Laptop
- Tablet
- Mobile

---

# Animations

Only subtle animations are required:

- Fade In
- Hover Effects
- Smooth Scrolling
- Button Hover Animation

No excessive motion.

---

# Accessibility

The interface should support:

- Full RTL Layout
- High Contrast
- Readable Font Sizes
- Large Clickable Areas
- Visible Focus States

---

# Deliverables

At the end of Phase 1, users should be able to:

- Explore the platform.
- Learn about Wasal.
- Navigate to the AI Assistant.
- Ask general questions without logging in.
- Create an account.
- Log into the platform.

The complaint generation workflow will be implemented in Phase 2.
